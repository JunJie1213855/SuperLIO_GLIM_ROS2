# STD + TEASER++ + GICP + iSAM2 在线回环实施预案

日期：2026-10-27。状态：设计准备，未接入算法、未验证性能。适用于当前 ROS 2 工作区。

## 1. 目标与项目边界

第一阶段由 SuperLIO-SLAM 完成各会话的在线建图与回环；第二阶段导出优化关键帧与位姿，通过 GLIM 完成会话间子图配准、联合优化和地图合并。

```text
LiDAR / IMU → SuperLIO → KeyFrame
                         ↓
              单关键帧 STD 候选排序
                         ↓
              候选两侧累计子图 → FPFH 对应点与几何检查
                         ↓
              TEASER++ 鲁棒粗配准（SE(3)）
                         ↓
              平面验证 + 局部子图 GICP 精配准
                         ↓
              残差、覆盖、退化和修正量验证
                         ↓
              iSAM2 回环边、优化轨迹、map→world
                         ↓
              优化位姿驱动地图重建
                         ↓
              src/tools 导出 → GLIM dump → 多会话合并
```

STD 负责检索，TEASER++ 负责从对应点估计粗变换，GICP 负责精配准，iSAM2 负责全局一致性。TEASER++ 不承担场景检索；输出有效标志也不能代替回环验证。

STD 保持单关键帧提取；粗配准和精配准使用多帧子图。首版增加候选子图内的 PCL FPFH 对应点构建，不引入距离候选、多会话在线检索或前端状态回写；保持输入消息和输出话题兼容。保留旧 STD+ICP 模式，用于同数据对照。

## 3. 坐标与因子契约

定义 T_A_B 将 B 坐标中的点变换到 A。当前中心关键帧为 c，历史中心关键帧为 h；存储点云均位于对应帧的扫描末时刻 IMU 坐标系。

- STD 顶点配对：source=current，target=historical。
- TEASER++ / GICP 均输出 `T_h_c`，满足 `p_h ≈ R_h_c p_c + t_h_c`。
- iSAM2 变量 `X_i = T_map_i`，回环观测 `Z_hc = T_h_c`。
- 因子残差：`Log(Z_hc^-1 * X_h^-1 * X_c)`；因子顺序固定为 `(h,c)`。
- 相邻里程计观测始终由原始 odom_pose 相减得到，不能用优化 map_pose 重算并覆盖旧边。
- TF：`T_map_world = X_k * inverse(T_world_k_odom)`，两项来自同一关键帧时刻。

回环不修改 ESKF、速度、IMU bias 或前端局部地图。world→imu 保持前端连续运动输出，map→world 承担全局修正。map 下当前位姿允许随回环跳变，不对历史优化位姿做平滑伪造。

## 4. STD 候选与对应点构建

新增 `SearchCandidates()`：返回候选 frame_index、粗匹配数量和 triangle_pairs；沿用哈希、年龄、边长及顶点附加特征过滤，按粗匹配数返回前 K 个候选。

新模式不把旧三角形投票或旧初值下的平面得分作为前置硬门限。TEASER++ 求得变换后再计算单关键帧平面几何得分；该指标是辅助验证，是否作为硬门限通过回放标定，避免单帧稀疏再次阻断子图匹配。候选不足时记录原因，不隐式切换成其他算法。

STD 三角形点对保留用于诊断、候选支持信息及单帧对照。多帧粗配准必须额外从累计子图生成对应点：仅把单帧 STD 顶点送入 TEASER++，不能称为多帧粗配准。

对每个候选：

1. 两侧注册子图分别降采样，计算局部法向和 PCL FPFH；这里 FPFH 只在 STD 选出的候选间建立对应，不负责全局检索。
2. 去除非法坐标、无效法向及无效描述子；记录法向邻域不足的点，低密度时拒绝或按已验证策略调整尺度。
3. 按 FPFH 特征距离进行互为最近邻匹配，可加最近/次近距离比筛选；特征相同或次近距离为零时显式处理。
4. 每个源/目标采样点采用稳定索引，去除重复与一对多冲突，限制最大对应点数，并按空间分布确定性抽样。
5. 检查唯一对应点数量、基线与中心化点集奇异值，拒绝近共线或范围过小的输入；不能把平面点集一概拒绝。
6. 不依赖旧 STD 初始位姿做很窄的空间距离筛选，避免其误差提前移除真实匹配。STD 顶点作为可选补充时须单独标识来源、跨来源去重，并做消融验证。

FPFH 法向和特征搜索半径随子图体素及密度标定；历史特征按成员索引、下采样和特征参数缓存，参数变化使缓存失效。初版使用 PCL 实现，无需启用 TEASER++ 上游的 teaser_features 封装。

候选只接受一次完整验证；失败后尝试下一候选。每个当前关键帧最多新增一条回环边，并限制验证候选总数。

## 5. TEASER++ 粗配准

封装 `TeaserCoarseRegistration`，输入两组 3×N 双精度对应点和参数，输出 `T_h_c`、原始对应点残差统计、耗时与失败原因。

- `estimate_scaling=false`，固定 LiDAR 米制尺度。
- 使用上游已有 GNC_TLS；不将“鲁棒估计”等同于已经执行最优性认证。
- 在线首版考虑 PMC_HEU，PMC_EXACT 作为离线对照；对应点、线程及最大团搜索时间都有限制。
- 检查 solution.valid、有限性、旋转正交性、det(R)≈1，以及对应点残差内点数和空间范围。
- 自行按原始点对重算残差内点，不把 TIM 的内点索引直接当成输入角点索引。
- TEASER++ 的 noise_bound 对应采样点对应的位置误差，需要随传感器和提取误差标定；不能直接照抄上游 0.01 m 默认值。

`max_clique_time_limit` 只限制最大团求解阶段，不是完整注册的硬超时。工作线程不能靠 std::future 超时后遗弃仍运行的任务来保证时延。首版通过输入/迭代/线程上限测量耗时；超过软预算停止启动后续候选。若实测无法满足响应要求，采用可终止子进程，而不是强杀 C++ 线程。

## 6. 子图 GICP 与验证

### 6.1 子图

STD 输入维持单关键帧；TEASER++ 和 GICP 共享同一对多帧子图及锚坐标。单帧注册保留作消融对照。先实现统一子图构建器和 FPFH 对应点，再接入粗配准和精配准。

默认当前子图由 `[c-L,c]` 构建，历史子图使用候选 h 对应的 `[h-L,h]`，两侧注册子图都采用因果窗口，只用已有帧。首轮建议每个子图最多 4 个关键帧（中心帧加此前 3 帧）。历史前后对称窗口仅作后续对照；启用时须重新构建并记录成员，须与当前候选的注册子图和特征缓存一致。排除有共享帧的候选对，避免相同数据造成虚高重叠率。

每个邻居点云用 `inverse(T_world_center_odom) * T_world_neighbor_odom` 变换到中心帧，保持短窗口原始里程计几何的一致性。两侧分别降采样、限制点数；FPFH 可使用更稀疏的采样，但锚坐标和成员集合保持一致。历史候选已经经过全局优化时，也不在同一个子图内混搭 odom/map 位姿。

### 6.2 精配准

使用 PCL GeneralizedIterativeClosestPoint，初始变换为 TEASER++ 的 T_h_c。初版单尺度，确认收益后再评估多尺度，不叠加 NDT。

GICP 协方差近邻数量必须小于可用点数；点数不足直接拒绝。检查收敛、有限变换、旋转有效性，并计算 `inverse(T_teaser) * T_gicp` 的平移和旋转修正。

### 6.3 独立验收指标

以独立最近邻评估统一计分，明确距离阈值以米为单位、平方误差以 m² 为单位。不要把 GICP 内部目标函数、PCL getFitnessScore 与独立统计混为一个分数；本机 PCL 1.12 的 getFitnessScore(max_range) 在实现中直接比较平方距离，不能无检查地传入米制半径。

- 源点覆盖率：源子图变换后落在目标阈值内的比例。
- 历史目标裁剪到当前可见邻域后，记录反向覆盖率；首版不直接对较大的完整历史子图强加对称覆盖门限。
- 内点 MSE、残差中位数及分位数，与覆盖率联合判断，避免只保留少数近点就得到低 MSE。
- 单独检查当前中心帧的覆盖率，防止历史累计帧掩盖当前帧错误匹配。
- 保留 TEASER→GICP 修正限幅；不将候选与 odom 的总差值硬限制为小漂移。
- 评估对应几何和适当归一化的配准信息矩阵，识别走廊/单平面弱约束。阈值先离线标定；首版保守拒绝严重退化候选，不将未经标定的 Hessian 直接当作可靠协方差。

通过后生成唯一 `LoopObservation{h,c,T_h_c,metrics}`。保持 Huber 鲁棒回环因子；鲁棒核不能替代前面的误回环过滤。

## 7. 图优化、并发与地图

分阶段执行：

- P1 首先保持现有串行关键帧处理，完成完整算法链和确定性测试。
- P2 独立地图工作线程：不可变点云共享指针 + 一致的优化位姿快照 + graph_revision；回环触发重建，普通新增关键帧可增量更新。
- P3 根据 P1 性能记录决定是否独立注册线程。图/STD 数据库由单一所有者修改；注册任务只读快照，结果带会话代号及帧索引，由图线程检查后添加迟到回环边。

迟到回环可以约束已存在的 c；每次回环后使用最新图节点的优化位姿更新 map→world，而非回到旧 c。排队上限与丢弃策略只丢弃过期注册任务，不能丢掉建图关键帧或里程计边。

全局显示地图按 `union(X_i * P_i)` 重建。重建期间保留上一完整版本；新回环使旧地图任务过期时，不允许旧结果覆盖较新版本。后台任务须可正常退出并 join。

显示地图与最终导出使用独立分辨率及点数策略；现有每帧显示上限 1000 点不能被误当作高质量保存标准。优化只刚体移动各帧点云，不能修复单帧去畸变误差。

## 10. 验证与准入

1. 固定数据、配置、软件版本，记录旧 STD+ICP+iSAM2 基线。对比 STD+GICP 与 STD+TEASER+GICP，随后比较单帧与局部子图，避免把所有收益归因于 TEASER++。
2. 对应点单测：已知 SE(3)、离群点、不重复加权、冲突、共线、平面、近等边排列与空输入；检查变换方向、尺度固定及确定性。
3. GICP 单测：已知旋转平移、低重叠、退化、点数不足和错误初值；检查评分单位及独立残差统计。
4. 图集成：原 stationary/moving/reject smoke test；新增长轨迹漂移回环，检查旧历史节点确实移动、首帧锚定、TF 同时刻一致、地图按优化位姿刷新。
5. 并发集成：迟到回环、连续两次回环、过期地图重建、停止退出、队列积压和会话重启；不接受旧会话结果写入新图。
6. 实际 bag：Robosense mapping、Unitree 重访和无回环负例；记录候选数、去重点数、每级拒绝原因、误回环、地图接缝、峰值内存、每级及总耗时 p50/p95/max、积压。
7. 有真值时算 ATE/RPE；无真值时只能报告配准/闭合残差和地图检查，不能宣称绝对精度提升。运行预算需实测确定；完整 bag 后待任务排空再导出，不能只报告处理速度而忽略未处理队列。
8. GLIM 回归：导出最终优化轨迹、检查每个时间戳的关键帧对应、map 点云不重复乘位姿、每个会话独立导出、转换 dump 后数量/位姿一致并能加载合并。

准入条件：合成测试中无错误边、方向和 TF 断言全部通过；实际负例无已知误回环，回访有人工/真值支持，内存与时延符合部署预算；无这些证据前新模式保持 opt-in，不替换旧默认模式。

## 11. 实施顺序与交付

- M0：依赖独立构建、固定传递依赖，记录旧方案基线。
- M1：STD 单帧候选接口、子图 FPFH 对应点与去重、TEASER 单测。
- M2：单帧 STD 检索及统一多帧子图的 TEASER++、GICP 与质量门限、回环因子接入；单帧及旧模式可切换。
- M3：单帧与 2/4/6 帧窗口 bag 对照，按传感器标定门限和窗口上限。
- M4：地图异步重建；根据性能需求实施异步注册。
- M5：完整回放、GLIM 转换合并回归、文档与默认模式决策。

本预案不承诺算法必然提高召回率或精度；特别是 STD 无描述子时，TEASER++ 也没有可用候选。后续若要覆盖此类场景，应单独评估距离/其他描述子检索，而不是调宽配准门限。

## 12. 多帧范围确认：只用于粗配准和精配准

按用户澄清，STD 继续对当前单关键帧提取描述子并检索历史单关键帧。只有注册阶段使用累计局部子图：

```text
单帧 STD → 候选历史中心帧 h
                   ↓
当前 [c-L,c] 子图 ↔ 历史 [h-L,h] 子图
                   ↓
子图 FPFH 对应点 → TEASER++ → GICP → iSAM2
```

### 12.1 统一坐标与处理顺序

对中心 c 的邻居 j：`P_c = voxel(union(inverse(O_c) * O_j * P_j))`，O_i 为原始扫描末时刻 IMU 里程计位姿。

当前点云在 onKeyFrame 中尚未存入 frames_，子图构建接口需要显式传入它及 raw_pose，不提前插入未完成的图节点。STD 维持 GenerateSTDescs(current_single_cloud) → SearchCandidates → AddSTDescs 顺序，冷却期间照常存储单帧描述子。

候选 h 与当前 c 决定子图锚点，两侧的粗配准点对应和 GICP 点云都在相应锚坐标中；T_h_c 直接成为中心关键帧对的 Pose3 观测。

### 12.2 窗口与存储

- 实验起点：最多 4 个关键帧，时间跨度不超过 6 s，累计路程不超过 6 m。数字均待回放验证。
- 向过去逐帧加入，任一上限达到即停止；路程按相邻位姿平移长度累加。只用过去帧，无需等待未来帧。
- Frame.cloud 保持单帧内容。RegistrationSubmap 单独记录锚索引、成员索引、下采样及特征参数；历史子图和 FPFH 可按这些键缓存或确定性重建。
- 成员集合相交的候选对直接拒绝，避免共享点云造成虚高匹配率。
- 相邻子图高度重叠，限制邻近历史中心候选的重复验证及重复回环边。
- 优化显示地图和 GLIM 导出继续使用单帧 cloud 和优化位姿；不能导出重复的滑窗子图代替单帧数据。

### 12.3 采样与验收

这里的帧指关键帧，当前按 1.5 m / 10° / 3 s 选取；它们不同于连续原始扫描。后续若要累计未发布的原始扫描，需要前端提供每次扫描的位姿及明确的数据接口，属于独立改造。

多帧可以增加结构与覆盖，也可能引入局部漂移、动态点和重复特征。对比 1/2/4/6 帧注册窗口，STD 输入保持不变，以分离累积带来的收益。

新增验收：已知运动下子图对齐；短窗口与时间/路程截断；FPFH 非法/重复特征；共享成员拒绝；粗精配准相同锚坐标；回环不改原始子图几何；单帧地图导出点数不被滑窗放大。STD 无候选时不运行子图粗配准，明确记录该限制。

## 13. deque 滑窗子图管理

按用户要求，当前注册子图采用 `std::deque` 管理。它只管理注册窗口，不替代历史关键帧存档或 STD 数据库。

### 13.1 数据模型

建议新增 `include/loop/SubmapWindow.hpp` 和 `src/loop/SubmapWindow.cpp`，由后端关键帧处理线程单独持有：

```cpp
struct WindowEntry {
  std::size_t frame_index;       // 连续后端索引
  double stamp_sec;
  gtsam::Pose3 odom_pose;        // 原始 T_world_frame
  Cloud::ConstPtr cloud;        // 单帧局部点云，共享只读
  double cumulative_distance;  // 从会话开始的累计里程计路程
};

class SubmapWindow {
  std::deque<WindowEntry> entries_;
  // appendAndTrim(entry, limits)
  // snapshot() -> immutable entries + anchor/frame_indices
};
```

deque 可访问队首、队尾及成员，便于按多个约束裁剪并获取快照；std::queue 不方便遍历和子图重建，因此首选 deque。

每个输入只有在位姿、点云有效且被确定接收后才进入滑窗。实际实现须让关键帧存储、窗口状态和图节点索引一致；预处理/候选提取失败时不能留下同索引的窗口残项。建议用临时窗口快照执行构建与提取，再在关键帧接收成功时提交窗口；后续注册失败只拒绝回环，不丢弃合法里程计节点。图更新不可恢复失败时保留现有 backend_faulted 语义，停止继续写入。

### 13.2 入队、裁剪和锚变换

1. 计算当前帧相对前一个已接收关键帧的平移长度，累加到 cumulative_distance，队尾加入当前条目。
2. 当 size 超过上限，或尾首时间差超过上限，或尾首累计路程差超过上限，移出队首；至少保留当前帧。参数为零是否表示禁用必须在实现中统一定义，不能使窗口变空。
3. 当前中心帧始终为队尾 c。遍历快照，将每帧局部点云按 `inverse(O_c) * O_j` 变换后合并、降采样和限制点数。
4. 每次锚点变更都从局部点云重建注册子图；首版不增量反复变换已合并云，避免累积数值误差及无法正确移除旧点。
5. 队首移出只释放窗口持有的引用，不删除历史 Frame、STD 描述子、里程计边或地图数据。

时间必须使用传感器消息时间而非 wall time；会话重启清空窗口和累计路程，乱序/重复关键帧在入队前拒绝。前端时间倒退不得使窗口无限增长。

### 13.3 历史候选和缓存

历史关键帧继续由现有 frames_ 保存。每个候选 h 从存档中按相同因果窗口规则选取 `[h-L,h]` 成员，并在 h 坐标下重建；不要求把所有历史窗口各保存一份点云。

当前 deque 快照和历史成员索引集合用于检查共享帧。历史 FPFH/注册子图可使用有容量上限的 LRU 缓存，键至少包含中心帧索引、实际成员集合、预处理参数版本。只要基于不可变原始 odom/cloud，图优化不使这些注册缓存失效；改用优化位姿构图则需要 graph_revision，本方案暂不采用。

窗口内共享指针和存档共享同一单帧云；FPFH 和注册合并云的内存单独统计。限制 deque 大小只能限制当前窗口，不代表 frames_、STD 数据库或历史缓存的总内存已受控。

### 13.4 与异步及地图的关系

首版仍单线程更新 deque；注册任务接收不可变快照和参数，不持有 deque 迭代器，不直接读写正在修改的 frames_。后续异步任务队列与这里的滑窗 deque 是两种独立结构：前者管理任务积压，后者管理点云成员。

地图重建线程使用优化位姿快照和单帧云，不复用正在变化的注册窗口。GLIM 导出契约保持不变。

### 13.5 新增验证

- 入队和帧数/时间/累计路程三种裁剪条件分别生效，窗口至少一帧。
- 转弯回到近处时，累计路程上限仍生效，不用首尾直线距离代替。
- 移出队首后单帧存档仍可构建历史候选子图。
- 预处理失败、重复/乱序、时间倒退及会话重启不会污染窗口或帧索引。
- 新帧使锚坐标变化后，与从原始单帧重新计算的子图一致。
- 异步注册运行期间继续入队，已有快照内容保持不变；验证缓存容量与共享指针生命周期。

## 14. 数学推导
